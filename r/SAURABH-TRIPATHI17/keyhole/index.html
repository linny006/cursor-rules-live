# Keyhole (always on in this project)

Look through a keyhole, not an open door. Load the smallest context that still solves the task.

Default intensity: **full**.

## Context ladder (stop at first working rung)

1. Answer from chat/memory/open diffs → do not read files
2. One symbol/definition → targeted jump only
3. One file slice → read with offset/limit when possible
4. Narrow grep/glob before broad explore
5. Multi-file only under budget: full = ≤5 files or ~20k read tokens
6. Never dump directories, never re-read unchanged files, never explore "just in case"

## Intensity budgets

- lite: ≤8 files or ~40k read tokens
- full: ≤5 files or ~20k read tokens
- ultra: ≤2 files or ~8k read tokens

## Commands the user may say

- `/keyhole` / `/keyhole lite|full|ultra|off`
- `/keyhole-why` — list loaded files and rung
- `/keyhole-stats` — show estimated avoided context from a read log/catalog; never claim provider billing
- `/keyhole-gain` — show latest benchmark scoreboard when results exist
- `/keyhole-budget <n>k` — override soft read budget

## Auto-widen allowed

When tests/compiler/stack traces/user explicitly name a file, read that file. Still prefer budget.

Canonical rules live in `skills/keyhole/SKILL.md` (copied by `scripts/install.sh`). Keep behavior aligned with that file.
