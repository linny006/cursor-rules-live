# Created with AI assistance; checked before release by the publisher (arrenite).

# Working agreement

- Read `docs/PRD.md` and `docs/TASK-PLAN.md` before starting. Work on one task ID at a time.
- Restate the task, the files you expect to change, and your test approach before editing.
- Stay inside the in-scope list. If a change outside it seems needed, stop and explain why.
- Do not add dependencies, change build or CI config, or alter public interfaces without asking.
- Write or update tests for every acceptance criterion you touch. Run them and report the result.
- Never hard-code secrets, tokens, or personal data. Use the existing config mechanism.
- When something is ambiguous, list the options and ask; do not invent requirements.
- Finish with a summary: what changed, why, tests run, known gaps, and new risks or assumptions
  to add to `docs/RISK-LOG.md`.
