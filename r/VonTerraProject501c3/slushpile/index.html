# slushpile

An adversarial job search lives under `.slushpile/` in this workspace. What the
review finds gets written back into the profile, so it compounds across roles.

When the user asks to set up a job search, search a careers board, assess a
role, build an application, or review one before sending it, read the matching
skill file and follow it in full:

| Task | File |
|---|---|
| Set up the workspace, once | `.slushpile/skills/onboard/SKILL.md` |
| Search and score roles | `.slushpile/skills/job-board-search/SKILL.md` |
| Open the warm channel for a role | `.slushpile/skills/outreach/SKILL.md` |
| Interview for undocumented experience | `.slushpile/skills/explore-experience/SKILL.md` |
| Build a resume and cover letter | `.slushpile/skills/application-builder/SKILL.md` |
| Seven-agent adversarial review | `.slushpile/skills/adversarial-review/SKILL.md` |
| Restyle the document templates | `.slushpile/skills/redesign-templates/SKILL.md` |
| Report search state and calibration | `.slushpile/skills/status/SKILL.md` |

Agent personas for the review are in `.slushpile/agents/`. Workspace templates
are in `.slushpile/templates/`.

Two standing rules:

**Read `preferences.yaml` and `profile.md` before making any claim about the
user.** Nothing in the pipeline hardcodes a personal fact. If it is not in one
of those files, it is not true about this user, and it does not go in an
application.

**Never submit anything.** This pipeline writes files. The user reads them and
sends them.
