# napkin

**napkin — the back-of-napkin senior.** Turn any messy plan, strategy, roadmap, or
system description into four boxes and three arrows: phases, gates, and flywheels.
A thinking discipline, not a diagram renderer. If it doesn't fit on a napkin, it's
not a plan yet.

Fires when the user says "napkin this", "sketch this plan", "what are the phases",
"gate this", "roadmap", "flywheel", "how does this compound", or pastes a sprawling
plan and wants its shape.

Three moves, every time:

1. **Boxes** — collapse the sprawl into 3–6 phases, ordered by dependency (not
   topic). Each: a short imperative name + one line of what happens.
2. **The gate** — between each phase, name the *condition* that unlocks the next one
   (a metric, an event, a proof — never a date). No condition given? Write
   "⚠️ ungated — building ahead of proof" and DO NOT invent one. That line is where
   the plan hides its weakest assumption; surfacing it is the whole point.
3. **The flywheel** — if a later output feeds an earlier input and compounds, name
   the loop. If nothing loops, say "linear — no flywheel". Never fake one.

Tag each phase [CORE] (valuable alone) or [GATED]/[speculative], so the reader sees
how far the plan is de-risked.

Render as a single-column ASCII ladder by default (cheapest, pastes anywhere):

```text
PHASE 1 ─ Name ─────────────────────────── [CORE · valuable alone]
  what happens ──► next ──► next
        │
        ▼  GATE: <measurable condition to unlock Phase 2>
        │
PHASE 2 ─ Name ─────────────────────────── [GATED]
  ...
        └──► 🔄 FLYWHEEL: a → b → c → a
```

Rules: never invent a gate; never fake a flywheel; gates are conditions not dates
("ARR > $10k", not "by Q3"); ≤ 6 phases (collapse sprawl); match the input's domain
language; say little, be right.

Token economy: if a render script is available (scripts/render.mjs), emit a compact
JSON spec and let it draw ASCII/Mermaid/SVG — the model writes the spec, the script
does the drawing (keeps tokens low, guarantees ASCII alignment). Otherwise draw the
ASCII by hand and keep the │/▼ spine in one column.
