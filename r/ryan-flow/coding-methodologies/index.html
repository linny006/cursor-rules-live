# AI Agent 调试方法论

来源：https://github.com/ryan-flow/coding-methodologies

## 约束优先排查（Constraint-First Debugging）

**核心原则：先验证不可控层是否支持，再决定是否在可控层投入精力。**

很多功能看起来是「代码写得不对」，实际是「平台根本不支持」。搞反了就是浪费时间。

### 什么时候触发

- 尝试实现某个功能但不确定能不能做成
- 涉及第三方 API / 平台限制
- 调试时感觉在绕圈子、改了很多代码但问题依旧
- 用户问「能不能做到 X」

### 排查层级（自底向上）

1. **平台 / API 层**（不可控）— 官方文档、API reference、已知限制
2. **协议 / 格式层**（半可控）— 数据格式、编码、传输协议
3. **代码 / 逻辑层**（可控）— 我们能改的一切

### 执行步骤

1. 明确目标：要实现什么具体效果？
2. 查文档：目标平台的官方文档是否明确支持这个能力？
3. 找证据：搜索社区、GitHub issues，确认有没有人成功过
4. 快速验证：用最简单的方式（curl / 一行代码）直接测试 API 是否接受这个请求
5. **API 层不支持 → 停下来**，不要试图通过改客户端代码绕过去
6. API 层支持 → 再往代码层排查

### 动手前检查清单

- [ ] 官方文档里有没有明确说支持这个功能？
- [ ] 有没有人成功实现过？
- [ ] 最简单的 API 调用测试做了吗？
- [ ] 如果不支持，有没有替代方案能达到 80% 效果？

### 反面案例

目标是让机器人发出某平台的原生语音气泡。错误路径：改发送代码 → 装编码器 → 改正则 → 改扩展名识别，一路改下去。最终发现是平台服务端直接拒绝该消息类型，客户端怎么改都没用。**代价：2-3 小时的修改全部作废。**

正确做法是第一步就用 curl 直接调 API 发一条，看返回值。

## Windows UTF-8 安全编辑

**核心原则：中文 Windows 的 ANSI 代码页是 936（GBK），PowerShell 5.1 的 `Get-Content` / `Set-Content` / `Out-File` 默认按 ANSI 处理文本，中文在读入那一刻就已损坏，之后无论用什么编码写出去都救不回来。**

### 什么时候触发

- 在中文 Windows 上编辑、生成或批量重写文本文件
- 用 PowerShell 读写文件内容
- 写含中文的 git 提交信息、导入 SQL
- 输出出现乱码

### 第一原则

能用 UTF-8 安全的文件工具（Read / Write / StrReplace）就不要用 shell 改文本。shell 留给真正的系统命令。批量改文本改成写 Node 脚本执行——`readFileSync(p, 'utf8')` 不受代码页影响。

### 先分清文件坏了还是只是显示坏了

| 现象 | 含义 | 处置 |
|---|---|---|
| 变成密集的生僻汉字 | 文件真的坏了 | 从 git 恢复后重做 |
| 变成问号或方块 | 只是控制台显示问题 | 设置控制台编码即可 |

### 不得不用 PowerShell 时

```powershell
$p = (Resolve-Path 'file.ts').Path
$lines = [IO.File]::ReadAllLines($p, [Text.Encoding]::UTF8)
[IO.File]::WriteAllLines($p, $lines, (New-Object Text.UTF8Encoding $false))
```

`UTF8Encoding $false` 表示不带 BOM；`Set-Content -Encoding UTF8` 在 PS 5.1 会写出 BOM，多数仓库不接受。

含中文的 git 提交：PowerShell 没有 heredoc，把消息写进 UTF-8 无 BOM 文件后 `git commit -F 文件`。
导入 SQL：禁止 `Get-Content x.sql | mysql`，改用 cmd / Git Bash 下的重定向 `mysql --default-character-set=utf8mb4 db < x.sql`。

**改完必须验证**，否则等于把乱码提交进仓库。

### 相邻的 PowerShell 陷阱

- `src\**\*.vue` 不会递归，`Select-String -Path` 会静默漏文件给出假阴性
- `stash@{0}` 要加引号，`@{` 是哈希表字面量语法
- `??` 是 PowerShell 7 语法，5.1 不支持
- `&` 在字符串外是保留字符，远程命令用 `;` 分隔
