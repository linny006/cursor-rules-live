# Master-Planner Bootstrap

This project has the Master-Planner harness installed under `.cursor/`.

## When planning is requested

If the user wants to plan, architect, spec, design, or figure out how to build something — including `/mp-plan`, "how should we build", PRD, roadmap, or resume planning:

1. **Read** `.cursor/skills/master-planner/SKILL.md` immediately and follow its pipeline.
2. **Do NOT** switch to Cursor native Plan mode or use `CreatePlan` / `SwitchMode` to `plan` for project planning in this repo. That produces ephemeral Cursor UI plans, not durable harness artifacts.
3. Persist state under `.cursor/plans/<project>/` (`manifest.md`, `spec.md`, `tasks.md`, `context.md`).
4. Obey `001-planning-safety`: no production implementation before plan approval.

## Primary slash command

Use **`/mp-plan <intent>`** to start or continue planning.

Do **not** rely on bare **`/plan`** — on most Cursor builds it triggers the IDE's native Plan mode instead of this harness.
